Services

Software development, end to end.

I design, build and deploy software for teams and organisations: web, mobile, back end, GIS and AI. One engineer responsible from requirements to release.

Scope

What I build.

  • Web applications

    Browser-based products and internal tools, from the interface to the database. I build front ends in Angular and TypeScript on Go services. See MapSmith and NammaTN.

  • Mobile apps

    Native iOS apps in SwiftUI and Android apps in Kotlin, including offline use and background sync, as I built for JurisField.

  • Back ends, APIs and data

    Go services, PostgreSQL schemas, sign-in with Keycloak and OpenID Connect, file storage and the APIs other systems call.

  • GIS and geospatial

    PostGIS, MapLibre, vector tiles, spatial analysis and map dashboards. This is the core of MapSmith.

  • AI agents and automation

    Agents that handle part of a workflow, with review steps for people and MCP integration to your own systems. Atlas, my own video pipeline, has MCP integration for agent access.

  • RAG and knowledge systems

    Search and answers over your documents and data, built so each answer points to the source it came from.

  • Systems and performance

    Lower-level work in C and C++. At Zoho I debugged and extended a production real-time media server.

  • Deployment and operations

    Docker-based releases, self-hosted and on-premises installs, multi-tenant setups, and the tests and checks around them.

Ways to work

Three ways to engage.

  • A new build

    A product or internal system from first requirements to deployment.

  • An existing project

    New features, a stalled delivery, or a system that needs untangling.

  • A consultation

    A second opinion on an architecture, a technology choice or a plan.

Process

How an engagement runs.

  1. Understand

    I walk through the work with the people who do it and write down what the first version must handle.

  2. Prototype

    I build a working version early, so we review real software and not a document.

  3. Build and test

    The agreed scope, with automated tests and review of every change before it ships.

  4. Deploy and improve

    Release to your environment, then changes guided by the people using it.
